Guia de revisão — Sprint 1

Projeto: Inventário de Ativos e Vulnerabilidades · Linguagem: Python · Interface: terminal

Como usar este guia: ele explica as decisões tomadas no projeto e revisa todos os cartões S1_01 a S1_20. Os links “cartão” levam à fonte da disciplina; as referências finais reúnem os materiais que aparecem nos cartões.

1. O que o projeto resolve

O programa registra ativos de TI — por exemplo, notebook, servidor e roteador — e suas vulnerabilidades. Tudo funciona pelo terminal e os dados ficam no arquivo dados/inventario.json.

  • Um ativo possui ID, nome/hostname, responsável, localização, tipo e lista de vulnerabilidades.
  • Uma vulnerabilidade possui descrição, categoria, severidade e status de tratamento.
  • O menu permite cadastrar, listar, buscar, atualizar, remover, salvar e consultar os dados.

2. Decisões de código, passo a passo

Dados em dicionário

O programa usa ativos = {}. A chave é o ID inteiro do ativo, por exemplo ativos[10]. Assim, verificar se um ID já existe, buscar e remover é direto. Cada ativo também é um dicionário e a sua lista vulnerabilidades guarda os registros associados.

Enum para tipos de ativo

TipoAtivo(IntEnum) associa códigos inteiros a nomes como NOTEBOOK = 1 e SERVIDOR = 2. O usuário digita um número simples; o programa confere se ele existe antes de salvar.

Funções pequenas

Cada ação do menu tem uma função: cadastrar_ativo, buscar_ativo, atualizar_ativo e assim por diante. Isso evita repetir código e facilita explicar a lógica: o menu decide qual função chamar e a função executa apenas aquela tarefa.

Validação e erros

ler_inteiro usa try/except para não encerrar o programa quando alguém digita letras no lugar de um número. Na leitura do JSON, erros de arquivo, JSON malformado ou formato inesperado retornam uma base vazia. DadosInvalidosError mostra o uso de raise para um formato que não deveria ser aceito.

Persistência em JSON

salvar_ativos transforma o dicionário em JSON com json.dump. Ao iniciar, carregar_ativos faz o caminho inverso com json.load. Por isso os dados continuam existindo ao fechar e abrir o programa.

3. Como executar e testar

  1. Abra o terminal na pasta do projeto.
  2. Execute python app.py.
  3. Cadastre um ativo pela opção 1, preenchendo ID, nome, responsável, localização e tipo.
  4. Cadastre uma vulnerabilidade inicial ou use a opção 6 depois.
  5. Use 2, 3, 4, 5 e 7 para conferir lista, busca, atualização, remoção e vulnerabilidades.
  6. Feche com 0, execute novamente e use 2: o ativo salvo no JSON deve continuar disponível.

5. Git: o que foi feito e por quê

  1. Iniciar: git init transforma a pasta em repositório e git add escolhe arquivos para o próximo commit.
  2. Registrar evolução: git commit -m "mensagem" cria pontos de retorno e explica cada etapa.
  3. Publicar: git push -u origin main envia a branch principal ao GitHub; git pull traz mudanças do remoto.
  4. Isolar mudança: git switch -c nome-da-branch cria uma linha de trabalho separada.
  5. Integrar: git merge junta o trabalho pronto à main. Se duas mudanças alterarem o mesmo trecho, os marcadores de conflito indicam exatamente o que decidir.
  6. Revisar no GitHub: o Pull Request compara branch de origem e destino, guarda descrição e comentários e registra a integração.
